# Hemiso_DB

개인 성충·라인 관리 사이트. KML의 관리 흐름을 바탕으로 개인 기록에 필요한 기능만 구성했습니다.

- Google 로그인: 허용 계정 한 개만 서버에서 접근 가능
- 성충 등록·수정·삭제, 사진, 종·혈통·누대, 부모·조부모 계통 조회
- 교배 라인, 부모 연결, 유충 교체·무게 기록
- BeetleLog 성충·라인 선택 가져오기 (부모·유충 함께 가져오기)
- 연결된 기록의 양방향 동기화 및 충돌 보호
- 종·성별·상태 검색, JSON 백업, 모바일·홈 화면 추가
- 알림·댓글·회원 커뮤니티 없음

## 배포

`main` 브랜치를 공개 GitHub 저장소 `Hemiso_DB`에 업로드한 뒤 Settings → Pages → Source를 GitHub Actions로 설정합니다. 워크플로가 정적 파일만 묶어 배포합니다.

Supabase → Authentication → URL Configuration → Redirect URLs에 `https://ljy5747.github.io/Hemiso_DB/`를 **추가**합니다. 기존 BeetleLog/KML Site URL과 리디렉션 설정은 유지합니다. Google provider callback은 기존 Supabase URL을 유지합니다.

프론트엔드 `app.js`에는 공개 가능한 publishable key만 사용합니다. DB SQL은 이미 적용되었으므로 새로 실행하지 않습니다. 실제 사육정보·백업·사용자 사진을 공개 저장소에 커밋하지 마세요.

## 연동 범위

BeetleLog 연동 화면에서 가져올 항목을 직접 선택합니다. 이후 불러오기와 반영 버튼으로 연결된 기록을 갱신합니다. 양쪽에서 수정한 기록은 충돌로 표시하며 자동 덮어쓰지 않습니다. Hemiso에서 새로 만든 미연결 기록과 삭제는 BeetleLog로 자동 전파되지 않습니다. 알림은 등록하지 않습니다.

## 사육 분석

`사육 분석`에서 종·성별·라인별 체장, 유충 최대 체중, 용화 무게, 환원율을 비교합니다. 환원율은 **우화 체장(mm) ÷ 용화 무게(g)** 이며, 최대 유충 체중으로 대체하지 않습니다. 종은 공백과 영문 대소문자를 정규화해 구분합니다. 기본 성별은 수컷입니다. 전체 성별 선택 시 암수가 함께 집계됩니다.

용화 무게는 성충 수정 또는 라인 상세 → 유충 기록 수정에서 입력합니다. 용화 무게를 직접 입력하지 않으면 BeetleLog에서 가져온 `source_data.pupation.pupaWeight`를 사용합니다. `pupal_weight`는 연결된 개체의 BeetleLog 용화 무게와 양방향 동기화됩니다. 입력을 지우면 양쪽 값이 비워집니다. 성충 목록과 유충→우화 기록은 중복 집계를 방지하기 위해 분석 대상을 분리합니다. 0 이하와 누락 측정값은 계산에서 제외하며, 평균 환원율은 개체별 환원율의 산술평균입니다.

라인별 평균 및 표본 수, 용화 무게–우화 체장 산점도, 날짜순 성장 곡선, CSV 내보내기를 제공합니다. CSV는 선택한 필터를 따릅니다. 외부 분석 API나 AI 없이 로그인 후 불러온 기록을 브라우저에서 계산합니다.

## 양방향 수정

성충 목록의 수정 버튼, 라인 상세의 유충 수정 버튼에서 기록을 편집합니다. 연결된 성충·라인·유충은 저장 시 `hemiso_save_record`가 Hemiso와 BeetleLog를 한 트랜잭션으로 수정합니다. 용화 무게, 우화 체장·날짜, 성별, 병별 먹이·용량·체중도 함께 반영됩니다.

BeetleLog에서 변경한 연결 기록은 로그인 후, 창으로 돌아올 때, 보이는 화면에서 30초마다 불러옵니다. 편집 중에는 자동 갱신을 멈춥니다. 편집을 시작한 버전을 유지하며, 그 사이 다른 화면이나 BeetleLog에서 변경한 기록은 저장을 거절하고 입력 내용을 유지합니다. 최신 기록을 확인한 뒤 다시 수정합니다.

새로 만든 미연결 기록과 삭제는 자동으로 BeetleLog에 생성·삭제되지 않습니다. 이미 연결된 기록의 수정에 적용됩니다. 기존에 남아 있는 미반영 수정은 연동 화면의 수동 반영으로 보낼 수 있습니다.
